# 小柠自然语言 Agent、断线恢复与本地语音设计

## 目标

在保留现有本机 Agent 安全护栏的前提下，让 QQ `<configured-qq-id>` 通过自然语言直接委托任务，并获得经过验证的结果和真实文件；任务在 AstrBot 或 OneBot 短暂断线后可安全恢复；默认文字回复，仅在对方明确要求语音时返回本地合成语音。

“完成任务”必须同时满足：执行进程已结束、结果经过可验证检查、交付物经过隐私过滤并实际发送。模型口头声称“完成”不构成完成证据。

## 范围

本轮包含：

- 自然语言任务、状态、取消和高风险确认入口。
- 单任务持久队列、阶段进度、可重放任务的断线恢复和交付去重。
- Gemini Flash 语音输入理解、本地 TTS 输出及文字降级。
- 对新增加密数据、语音文件和日志的隐私保护。

本轮不包含：

- 向其他 QQ 用户开放本机 Agent。
- 修改 Claude Code、Codex、WorkBuddy 或 cc-connect 的全局配置。
- 未经授权克隆真人声音。
- 自动恢复删除、安装、权限修改、凭据操作、系统修改或向第三方外发等不可安全重放任务。
- 将 TTS 文本发送给 Microsoft Edge TTS 或其他新增云端语音服务。

## 总体架构

现有 `claude_code_agent` 继续作为唯一执行底座。新增能力只在其外层增加路由、队列与语音适配，不创建第二条绕过鉴权、风险审批、工作目录和交付过滤的执行路径。

组件边界：

1. `NaturalAgentRouter`：识别自然语言任务、状态、取消和确认意图，只负责路由，不直接启动进程。
2. `AgentJobService`：统一处理鉴权、风险判定、审批、排队、执行、验证、恢复和交付。
3. `EncryptedJobPayloadStore`：使用 Windows DPAPI 保存恢复所需的最小明文载荷的密文。
4. `JobStore`：扩展现有 SQLite 元数据账本，保存状态、阶段和去重摘要，不保存任务明文、路径、聊天目标或结果正文。
5. `VoiceReplyRouter`：决定是否需要语音输出，清洗待朗读文本并调用本地 TTS。
6. `LocalTTSService`：独立 Python 环境和独立本机进程，主引擎 GPT-SoVITS-CPUFast，备用引擎 MeloTTS，仅监听 `127.0.0.1`。

## 自然语言交互

### 触发条件

- 发送者必须精确等于 QQ `<configured-qq-id>`。
- 私聊可直接委托；群聊必须真实 @ 当前机器人。
- 明确动作表达，如“帮我整理这些文件并发回来”“用 Codex 修复这个报错”“看看任务进度”“取消刚才的任务”“确认执行”，进入 Agent 路由。
- 普通知识问答、情绪聊天和含糊表达继续走聊天模型。
- 路由采用确定性身份与会话门禁、动作规则和保守意图判断。模型只辅助理解意图，不能决定权限、风险等级或目录边界；判断失败时按普通聊天处理。

### 命令兼容

现有 `/agent use|cwd|run|approve|status|cancel` 全部保留，作为诊断和兼容入口。自然语言入口最终调用相同的 `AgentJobService` 方法。

### 后端选择

- 未指定时使用当前已选后端，默认 Claude Code。
- “用 Claude/Codex/WorkBuddy”只影响本次任务，不修改全局配置。
- 后端不可用时返回简短失败原因，不自动切换到另一个本机 Agent，避免行为漂移。

## 鉴权与审批

- 所有执行、确认、状态和取消操作均重新校验 owner 身份和会话范围。
- 群聊中的自然语言确认仍要求真实 @。
- 低风险且可安全重放的任务直接执行。
- 删除、安装、权限/系统修改、凭据处理、向原会话以外的目标外发等高风险任务必须二次确认。
- 自然语言“确认执行”与现有一次性确认码共享同一审批记录；审批绑定 owner、会话、任务摘要、后端和工作目录，5 分钟有效且只能消费一次。
- 改变工作目录或任务内容会使旧审批失效。

## 任务状态与进度

主状态机：

`queued -> awaiting_approval（仅高风险） -> running -> verifying -> delivering -> completed`

运行态包括 `queued`、`awaiting_approval`、`running`、`recovering`、`verifying`、`delivering`。`interrupted` 是重启恢复期间的过渡标记，可转入 `recovering` 或 `recovery_blocked`。终止状态为 `completed`、`failed`、`cancelled`、`timeout`、`recovery_blocked`。

- 同一时间只运行一个本机 Agent，后续任务进入有界队列。
- 默认只发送“已开始”“需要确认”“完成/失败”三类消息。
- 任务超过 3 分钟且阶段发生变化时最多补发一次进度，避免刷屏。
- “进度怎么样”返回任务编号、当前阶段、后端和已用时间，不显示任务原文、工作目录或本机路径。
- 取消操作终止完整子进程树，并把队列/密文/状态同步到一致终态。

## 加密载荷与隐私

为实现断线恢复，需要持久化任务文本和回复目标。它们不能写入现有明文 SQLite 字段，而是单独保存为 DPAPI 密文。

密文载荷只包含：

- 任务文本。
- 原会话回复目标。
- 本次后端和恢复所需的相对工作区标识。
- 恢复策略与必要的交付游标。

保护要求：

- 使用 Windows 当前用户范围 DPAPI；不在代码或配置中保存额外解密密钥。
- 密文目录关闭权限继承，仅当前 Windows 用户、SYSTEM、Administrators 可访问。
- SQLite 只保存任务摘要、HMAC 会话指纹、阶段、退出码、错误码、交付数量和时间。
- 任务达到终态后立即删除可重放密文；仅保留现有最小元数据审计记录。
- 日志不得记录任务正文、聊天目标、绝对路径、参考声线文件名、模型原始输出或 DPAPI 异常内容。
- DPAPI 只能防止其他账户直接读取磁盘；已控制当前 Windows 用户会话的攻击者仍可能解密。这是明确残余风险。

## 断线恢复与幂等性

恢复不是无条件重新运行。任务启动前由代码级策略同时计算风险等级和可重放等级。

可以自动恢复：

- 读取、分析、总结和测试。
- 在批准工作区内创建新文件。
- 对已有任务输出继续生成，且不会触发原会话以外的外发或系统级副作用。

必须暂停并重新确认：

- 删除、覆盖不可恢复数据、安装软件、修改权限或系统设置。
- 使用凭据、登录浏览器、支付或代表用户对外提交。
- 向原 QQ 会话之外的任何人或服务发送内容。
- 代码无法证明可安全重放的任务。

恢复流程：

1. 启动时把遗留 `running/verifying/delivering` 任务标记为 `interrupted`。
2. 校验元数据、DPAPI 密文、owner 指纹、会话指纹、工作区和恢复策略。
3. 可重放任务进入 `recovering`，复用原任务目录，并要求 Agent 先检查现有交付物再继续，禁止盲目从头覆盖。
4. 不可重放任务进入 `recovery_blocked`，只向原会话提示需要重新确认。
5. 交付阶段使用文件内容摘要和发送游标去重，避免重启后重复发送同一文件。
6. 密文损坏、解密失败或账本不一致时 fail closed，不执行、不回传可疑内容。

## 完成验证与交付

- 进程退出码必须为 0，否则任务失败。
- 文件任务必须确认交付物存在、为普通文件、位于允许工作区、大小和数量合规且不属于敏感类型。
- 代码任务优先运行任务声明的测试或最小相关验证；验证命令仍受现有风险与超时边界约束。
- 无法自动证明语义完成时，回复“执行结束，已完成以下可验证项”，不得把 Agent 自述提升为确定事实。
- QQ 群文件继续使用真实 OneBot 群文件上传；私聊使用文件组件。
- 对原请求会话的最终结果回传视为本次任务交付，不等同于允许 Agent 向其他目标外发。
- 交付前统一执行路径、密钥、令牌、密码和隐私文本脱敏。

## 语音输入与输出

### 输入路由

- 文字默认使用 `deepseek-chat`。
- 收到 QQ `Record` 时，由 `gemini-2.5-flash` 理解音频；群聊仍要求 @ 或唤醒规则。
- 收到语音不自动意味着语音回复。只有“发语音”“语音说”“用语音回答”等明确请求才设置语音输出标志。

### 本地 TTS

- 主引擎：[GPT-SoVITS-CPUFast](https://github.com/baicai-1145/GPT-SoVITS-CPUFast)，使用授权、自有或合成的女声参考音频。
- 备用引擎：[MeloTTS](https://github.com/myshell-ai/MeloTTS)，用于主引擎未就绪、超时或失败时的快速本地降级。
- 两个引擎运行在与 AstrBot 隔离的环境，防止 PyTorch、NumPy 和音频依赖污染现有机器人。
- TTS 服务只监听环回地址，并使用运行时本机令牌；不得暴露到局域网或公网。
- 声线目标为年轻、沉稳、清晰、自然的中文女声，不使用幼态卖萌或夸张情绪。
- 未取得授权参考声线前，GPT-SoVITS 不启用真人克隆，直接使用 MeloTTS 备用声线。

### 输出约束

- 待朗读内容先脱敏，再进入本地 TTS。
- 单次最多朗读 600 个中文字符，按自然语义切成不超过 3 段；更长内容用语音摘要并保留完整文字。
- Agent 任务完成语音只播报结果摘要，不朗读绝对路径、密钥、日志或大段代码。
- 输出音频写入私有临时目录，经 FFmpeg 转为 QQ/NapCat 可接收格式并发送 `Record`。
- 发送成功或失败后清理临时音频；失败时只回落为脱敏文字，不重复调用云端服务。

## 错误处理

- 自然语言意图不确定：按普通聊天处理，不执行。
- 安全审计或加密存储不可用：fail closed，本次任务不启动。
- 后端超时/崩溃：终止进程树、记录固定错误码、保留最小可恢复状态。
- OneBot 断线：完成验证后等待连接恢复，交付阶段去重重试；不重新执行已完成任务。
- GPT-SoVITS 超时：切换 MeloTTS；MeloTTS 也失败则回文字。
- 音频过长、格式不支持或 Gemini 失败：返回简短文字提示，不记录原音频内容。

## 测试策略

### 单元测试

- 自然语言任务/状态/取消/确认识别与闲聊误触发。
- owner、群聊真实 @、审批作用域和过期边界。
- 风险等级与可重放等级的组合矩阵。
- DPAPI 密文往返、篡改、错误账户/错误上下文和清理行为。
- 状态机合法迁移、恢复筛选和交付摘要去重。
- 语音输出意图、文本脱敏、长度切分和 TTS 降级。

### 集成测试

- 使用假后端验证自然语言任务实际进入现有执行服务，而非只生成聊天回复。
- 在 `running`、`verifying`、`delivering` 三阶段模拟重启。
- 验证可重放任务恢复，不可重放任务暂停，高风险审批不被复用。
- 验证本地 TTS 成功、主引擎超时降级和双失败回文字。
- 验证群文件真实上传接口、私聊文件组件和断线后的去重交付。

### 回归与运行态验收

- 现有 49 项 Agent 安全与 AI 群管测试必须继续通过。
- 新增测试全部通过，Python 语法编译通过。
- AstrBot 重启后插件加载、OneBot 重连，6185/6199 继续只监听本机，8192 继续不监听。
- 用无敏感信息的测试工作区完成一次自然语言文件生成和 QQ 回传。
- 用模拟重启验证一次可重放任务恢复；不使用真实删除、禁言、外发或真人声线做验收。

## 部署顺序

1. 抽取统一 `AgentJobService`，保持现有命令行为不变。
2. 增加自然语言路由和对应测试。
3. 扩展状态机、DPAPI 密文载荷和恢复/交付去重。
4. 建立隔离的 MeloTTS 服务并完成 QQ 语音闭环。
5. 在存在合法参考声线后接入 GPT-SoVITS-CPUFast；未满足时保持自动降级。
6. 全量回归、隐私扫描、重启和实际 QQ 低风险验收。

## 成功标准

- 小姚无需斜杠命令即可让小柠实际执行低风险任务并收到真实结果或文件。
- 高风险自然语言任务仍被一次性审批拦截，不能绕过现有安全边界。
- 可安全重放任务在 AstrBot 重启后继续并完成，不重复交付。
- 明确语音请求可收到本地生成的 QQ 语音；失败时可靠回落文字。
- 聊天、日志、SQLite、交付物和语音均不泄露机主路径、密钥、任务明文或未授权声线。
