# 小柠任务执行增强与体验升级设计

## 目标

让 Pro 用户通过自然语言提交任务后，小柠能完成“理解、计划、执行、验证、交付”的完整闭环；同时保持普通用户权限不变，并把回复、进度、记忆和语音体验收敛为简短、自然、可核验的风格。

## 固定边界

- Pro allowlist 仍只从本机配置读取，当前仅 QQ `1211000567`；聊天、人格和记忆均不能提升权限。
- 群聊触发 Pro Agent 必须真实 @ 小柠；私聊可直接提交。
- 工作目录内新增和修改文件可自动执行。
- 删除、覆盖既有文件、移动原文件、安装、部署、提交、上传、外发、登录、系统设置、权限与凭据操作必须二次确认。
- 未识别动作默认需要确认；自动恢复仅允许严格只读任务。
- 任务、回复、日志、记忆和交付物不得暴露本机绝对路径、密钥、令牌、浏览器凭据、私聊正文或无关私人文件。
- 当前完整权限 CLI 不是 OS 级沙箱；本轮增加策略隔离和可选 Windows 隔离执行，不宣称已实现数学意义上的完全隔离。

## 总体架构

所有自然语言任务进入唯一的执行管线：

`Task Intake -> Planner -> Policy Gate -> Backend Router -> Executor -> Verifier -> Deliverer`

不得为 Claude Code、Codex、WorkBuddy 或体验插件建立绕过该管线的第二执行入口。

### Task Intake

- 复用现有普通/Pro 鉴权、真实群聊 @、自然语言路由、任务长度限制和单任务队列。
- 将请求规范化为不可变的 `TaskRequest`：任务 ID、会话范围、发送者、目标、选定工作目录和显式后端偏好。
- 不在普通 SQLite 账本中保存任务原文；需要恢复的载荷继续使用当前用户 DPAPI 加密，终态删除。

### Planner

- 生成最多 8 个有序步骤，每步必须包含动作类型、预期产物、验证方式和是否有副作用。
- 计划只描述必要动作；禁止自行扩展到用户未授权的外发、登录、安装或系统变更。
- 单文件或单命令的简单任务可生成一个步骤，不强制制造复杂计划。
- 计划写入加密任务载荷；普通账本仅保存步骤数量、当前步骤和状态枚举。

### Policy Gate

- 每个步骤独立调用现有 fail-closed 动作分类器，不仅检查用户原始任务。
- `READ_ONLY` 与工作目录内“创建新文件/修改任务产物”可自动执行。
- 删除、覆盖原文件、外发、安装、部署、登录、系统/权限/凭据操作及 `UNKNOWN` 进入一次性确认。
- 确认绑定 Pro QQ、当前会话、任务 ID、步骤摘要和工作目录，5 分钟过期，只消费一次。
- 计划执行过程中若实际动作超出已批准范围，立即暂停并重新确认，旧确认不得复用。

### Backend Router

- 代码修改、测试、构建和仓库分析：优先 Codex；不可用时切换 Claude Code。
- 长文本分析、复杂推理或用户显式指定 Claude：使用 Claude Code。
- 已安装桌面软件的可视化操作：使用 WorkBuddy，但仍经过同一 Policy Gate。
- 用户显式 `/agent use` 作为偏好，不得覆盖安全策略。
- 每个无副作用步骤最多自动切换后端一次；有副作用步骤一旦开始，不自动换后端重做。

### Executor

- 保持单运行槽和有界队列；每步沿用现有进程树终止、超时和 stdout/stderr 硬上限。
- 默认在批准的工作目录执行；交付物只能进入任务专属 `outputs`。
- 可疑或未知但用户已确认的命令优先进入 Windows 隔离执行器；若任务依赖当前登录态或已安装软件而无法隔离，则明确提示边界后再等待用户选择，不静默降级为主机完整权限。
- 执行记录只保留固定状态、退出码、后端、步骤序号和摘要哈希。

### Verifier

- 不接受模型自述“已完成”作为证据。
- 编码任务至少验证相关测试、编译、静态检查或用户指定命令之一。
- 文件任务验证文件存在、大小、格式与任务要求；图片、压缩包和 Office 文件继续经过 DLP。
- 桌面操作验证目标窗口、文件或可读取状态；无法验证时标记为“执行结束但未证实”，不得标记完成。
- 验证失败时，只有无副作用步骤允许一次修复尝试；否则暂停并给出简短原因。

### Deliverer

- 先提交交付清单摘要，再发送文字与文件；重启后只补发未交付内容，不重复执行。
- 群文件继续使用 OneBot `upload_group_file`；私聊使用受控文件消息。
- 所有文件先经过允许根、符号链接、敏感名称、内容、归档和图片元数据检查。
- PDF 和未知二进制在没有专用安全解析器前保持 fail-closed。

## 小柠体验层

体验层只消费执行状态，不得直接调用本机工具。

### 回复风格

- 默认 1 至 4 句，先说结果，再说必要证据或下一步。
- 不重复用户原话，不输出内部计划全文，不堆砌“正在努力”等空进度。
- 失败时说明真实阶段、是否产生副作用、是否可安全重试。

### 进度播报

- 仅发送四类事件：已开始、需要确认、已完成、已失败。
- 超过 90 秒的任务可额外发送一次真实阶段更新；同一阶段不重复刷屏。
- 群聊不披露目录、文件路径、后台命令、模型输出或错误堆栈。

### 记忆

- 人格偏好：语气、称呼、回复长度与用户明确要求的稳定偏好。
- 关系记忆：仅保存用户明确要求记住的低敏感关系事实。
- 任务记忆：只保存任务类型、成功/失败、后端表现和匿名化经验，不保存任务正文、路径、文件内容或聊天记录。
- 凭据、健康隐私、私聊正文、本机目录、浏览器数据和未明确要求的第三方信息不得进入长期记忆。
- 记忆不参与 Pro 鉴权，不得改变安全策略。

### 语音

- 默认文字继续使用 DeepSeek；语音输入或明确要求语音输出时使用 Gemini Flash 处理语义。
- 输出优先使用经授权的本地高质量女声；未配置授权声线时继续使用 MeloTTS，不启用真人克隆。
- 朗读前继续删除代码、路径和凭据，限制 600 字、3 段；发送完成后删除 WAV，后台清理遗留音频。
- TTS 失败回退为脱敏文字，不影响任务状态。

## 状态与恢复

任务状态扩展为：`planned -> awaiting_approval -> queued -> executing -> verifying -> delivering -> completed`，失败状态为 `failed`、`cancelled`、`timeout`、`recovery_blocked`。

- 每个状态迁移必须合法且原子写入。
- 重启时只恢复严格只读且尚未执行完成的步骤。
- 已完成执行并提交交付摘要的任务只恢复交付。
- 工作区写入、高风险、未知或桌面操作任务重启后一律暂停，不自动重放。

## 错误处理

- 后端不可用：无副作用步骤切换一次后端；仍失败则停止。
- 验证失败：保留真实失败状态，不发送伪造文件或成功文案。
- 审计账本不可写：任务不执行；执行后账本写入失败则不交付结果。
- DLP 拒绝：只返回固定类别，不回显文件名、路径或敏感片段。
- 发送失败：保留交付游标，重启后补发，不重新执行。
- 隔离器不可用：不静默切换为不受限主机执行。

## 测试与验收

### 自动化测试

- 普通用户无法进入计划、状态、取消、确认、恢复和文件入口。
- Pro 工作区内低风险任务完整经过计划、执行、验证和交付。
- 计划步骤中的高风险动作即使原始请求看似低风险也必须暂停确认。
- 后端切换只发生在无副作用步骤且最多一次。
- 验证失败不能进入 `completed`。
- 重启不会重复执行已提交交付摘要的任务。
- 进度播报不重复、不包含路径、任务正文或异常正文。
- 记忆写入拒绝敏感类别，且任何记忆内容都不能提升权限。
- 语音失败回退文字，生成音频发送后清理。

### 真实 QQ 验收

1. Pro 私聊请求生成一个简单文本文件：收到开始提示、文件和可核验证据。
2. Pro 请求覆盖既有文件：只收到确认提示，确认前无副作用。
3. 普通账号提交同类任务：收到 Pro 边界提示且无任务记录。
4. 群聊 Pro 未真实 @：保持静默；真实 @ 后才执行。
5. 模拟发送中断：恢复后只补发文件，不重新运行 Agent。
6. 明确要求语音：收到本地语音；普通文字请求仍只返回文字。

## 实施顺序

1. 先实现任务计划、逐步策略检查、验证器和状态机。
2. 再实现后端路由、有限重试和可选隔离执行器。
3. 完成任务执行真实 QQ 验收后，再接入简短进度、分层记忆和高质量声线。
4. 每个阶段保持现有普通/Pro、DLP、ACL、日志和语音回退测试全部通过。

## 非目标

- 不开放新的 Pro QQ。
- 不允许聊天领取权限或邀请码升级。
- 不自动发送邮件、群消息或第三方内容。
- 不修改 Claude Code、Codex、WorkBuddy 的全局配置。
- 不在本轮解决全部 AstrBot 全局依赖冲突；如需处理，使用独立环境迁移方案。
