# Pro 申请与审核设计

## 目标

让 QQ 用户通过 `portelamicheli636@gmail.com` 提交 Pro 申请，并由小姚代表小江人工审核后开通受限 Pro 创作能力。公开申请永远不能获得本机 Agent 权限。

## 固定权限边界

| 层级 | 获得方式 | 能力 |
| --- | --- | --- |
| 普通版 | 默认 | 聊天、语音、提醒、公开查询、受群权限约束的群管理 |
| Pro | 邮箱申请、人工审核、QQ 验证 | 作图及其他明确标记为 Pro 的内容能力 |
| 本机 Agent | 不提供申请入口 | 仅 QQ `1211000567`；读取/修改项目、运行测试和文件交付 |

`trusted_pro_user_ids` 继续只允许 `1211000567`，申请通过、验证码验证、数据库篡改或配置热更新均不能改变本机 Agent 白名单。

## 申请流程

1. 用户发送 `/pro apply` 或“申请 Pro”。
2. 机器人生成无语义、不可预测的申请编号，记录申请 QQ、创建时间和 `pending_email` 状态；不保存邮件正文、邮箱密码或 Gmail 凭据。
3. 机器人展示固定邮件模板：收件人是 `portelamicheli636@gmail.com`，主题含申请编号，正文含 QQ 号、用途、申请能力和安全规则确认。
4. 用户发送 `/pro sent <申请编号>`，状态变为 `awaiting_review`。这不是自动通过。
5. 小姚在 Gmail 中人工核对申请编号、QQ 号和用途。Gmail 只作为人工审核收件箱；机器人不读取整个邮箱，也不自动发邮件。
6. 小姚使用只允许 `1211000567` 调用的 `/pro approve <申请编号> [天数]`。系统生成一次性 QQ 验证码，验证码仅与申请 QQ 绑定。
7. 用户从原 QQ 发送 `/pro verify <验证码>`。成功后 Pro 生效；默认 90 天。
8. 小姚可随时 `/pro deny <申请编号>` 或 `/pro revoke <QQ号>`；到期自动失效。

## 数据与安全

- SQLite 只存申请编号、QQ 号、状态、创建/到期时间、审核人、验证码哈希、失败次数和最小审计事件。
- 验证码为随机值，仅存哈希；有效期 10 分钟，最多 3 次失败，验证成功后立即失效。
- 同一 QQ 24 小时只允许创建一个未关闭申请；申请 72 小时未提交邮件确认则过期。
- 所有审核、撤销、授权查询命令必须校验审核人 QQ `1211000567`。
- 申请文本、邮件正文、Gmail Token、本机路径、私聊内容和 Agent 工作区不得进入数据库、QQ 回复或日志。
- Pro 成员读取使用本地数据库的有效期记录；作图插件在每次请求时检查有效 Pro 身份，不依赖重启或可编辑的静态白名单。

## 用户可见文案

- `/pro apply`：返回申请编号、邮件地址、模板、72 小时有效期及“Pro 不包含本机 Agent”的说明。
- `/pro sent`：确认已进入人工审核，不承诺通过时间。
- `/pro status`：只显示本人状态、到期日和下一步，不显示其他申请人或审核信息。
- `/pro verify`：只回复验证结果，不泄露验证码或审核资料。

## 审核命令

- `/pro pending`：仅审核人查看待审核的最小字段。
- `/pro approve <申请编号> [天数]`：范围 1–365 天，默认 90 天。
- `/pro deny <申请编号>`：关闭申请。
- `/pro revoke <QQ号>`：撤销 Pro。

## 验收条件

1. 普通用户可创建申请，但不能自行通过、续期或查看他人状态。
2. 错误 QQ、过期码、重复码和三次失败验证码均不能开通 Pro。
3. 仅小姚可审核、撤销和查看待审核列表。
4. 通过后作图立即可用；撤销或到期后立即不可用。
5. 申请通过后，普通 Pro 账号仍被本机 Agent 拒绝。
6. 全程不读取 Gmail、不中转邮件正文、不暴露机主隐私。
